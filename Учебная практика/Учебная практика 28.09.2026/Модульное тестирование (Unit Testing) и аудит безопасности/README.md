# Модульное тестирование (Unit Testing) и аудит безопасности

## Состав

- `test_material_calculator.py` — проверки ядра расчета: обычный результат, округление вверх, неизвестные типы, отрицательные/нулевые параметры и количество, некорректные числовые значения.
- `test_sql_security.py` — аудит `SELECT`, `INSERT` и `UPDATE` backend задания 21.09: идентификаторы и пользовательский ввод должны передаваться отдельными параметрами, не интерполироваться в SQL.
- `test_logging.py` — проверка timestamp, уровня и текста исключения в файловом журнале.
- `app_logging.py` — настройка файлового logger для приложения.

## Запуск тестов

Из этой папки используйте Python-окружение интеграционного backend задания 21.09, где установлены `psycopg2` и `python-dotenv`:

```bash
python3 -m unittest discover -s . -p 'test_*.py' -v
```

Тесты CRUD используют mock connection. Реальные запросы на запись в PostgreSQL не выполняются.

## Логирование приложения

Backend CRUD задания 21.09 пишет сообщения `logging.exception` в `app.log` с датой, временем и уровнем, а также продолжает выводить их в консоль. Файл игнорируется Git. Независимым модулям можно настроить такой же logger через `configure_app_logging()` из `app_logging.py`.

## Результат аудита SQL

CRUD-запросы используют placeholders `%s`; значения передаются вторым аргументом `cursor.execute(query, values)`. Тесты проверяют, что ввод с фрагментом SQL остается в параметрах и отсутствует в тексте запроса. Сортировка и имена колонок в запросах заданы статически.
