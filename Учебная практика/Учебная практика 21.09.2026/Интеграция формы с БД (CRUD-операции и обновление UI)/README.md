# Интеграция формы с БД (CRUD-операции и обновление UI)

## Реализовано

- API на Python/PostgreSQL: `GET /api/partners`, `GET /api/partners/{id}`, `POST /api/partners`, `PUT /api/partners/{id}`.
- SQL-запросы используют параметризованные значения.
- Реестр при открытии загружает текущие записи и рассчитанную скидку из БД.
- Карточка редактирования загружает партнера по ID; новая карточка открывается пустой.
- Форма включает ИНН, обязательный в исходной схеме и уникальный в БД.
- После `INSERT` или `UPDATE` страница возвращается в реестр, который повторно загружает данные.
- Ошибки API показываются рядом со списком или формой; подробности записываются в консоль сервера.

## Схема данных

Исходная `partners` не содержит тип партнера, адрес и ФИО директора. Миграция `migration.sql` добавляет недостающие колонки с безопасными значениями по умолчанию для существующих строк. Она уже применена к настроенной локальной БД этого проекта; на другой базе ее нужно применить один раз перед первым запуском.

## Настройка и запуск

1. Установите зависимости: `python3 -m pip install -r requirements.txt`.
2. Создайте `.env` на основе `.env.example` и заполните параметры подключения к PostgreSQL.
3. Примените `migration.sql` к нужной базе данных.
4. Запустите сервер из этой папки: `python3 server.py`.
5. Откройте `http://127.0.0.1:8005/index.html`.

Если рядом с практикой существует настроенный `.env` в папке интеграции с БД предыдущего этапа, сервер использует его; локальный `.env` можно добавить позднее для независимого запуска.

## Проверки без изменения БД

```bash
python3 -m unittest discover -s tests -v
```

Тесты подменяют соединение и проверяют валидацию, NULL/0 для скидки и параметризацию INSERT/UPDATE. Они не требуют запущенной PostgreSQL и не выполняют запись в настоящую базу.
