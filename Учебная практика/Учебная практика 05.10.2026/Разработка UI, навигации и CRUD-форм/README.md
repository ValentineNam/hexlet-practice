# Разработка UI, навигации и CRUD-форм

## Итоговое приложение

Эта папка объединяет итоговые части практик 14.09, 21.09 и 28.09:

- `MainWindow`: список партнеров из PostgreSQL, контактные данные и скидка по сумме реализации; в шапке есть иконка приложения и отдельный логотип компании.
- `PartnerEditWindow`: создание и редактирование партнера через `POST`/`PUT`.
- `PartnerHistoryWindow`: история реализации партнера через `JOIN` к `products`.
- Калькулятор материалов вызывает общий метод из `material_calculator.py`.
- SQL динамических запросов параметризован; CRUD-ошибки пишутся в `app.log` и возвращаются в UI.

Все экраны используют схему `practice_2026_10_05`, создаваемую заданием 1 этой практики.

## Запуск

1. Выполните ETL из папки «Инфраструктура данных и ETL», чтобы создать и загрузить схему.
2. Установите зависимости из этой папки: `python3 -m pip install -r requirements.txt`.
3. Создайте `.env` на основе `.env.example`, задайте параметры подключения и `DB_SCHEMA=practice_2026_10_05`.
4. Запустите `python3 server.py`.
5. Откройте `http://127.0.0.1:8010/index.html`.

Сервер и калькулятор используют общее подключение из `../Реализация ядра бизнес-логики (Расчеты и алгоритмы)/database.py`. Приоритет: переменные процесса, локальный `.env` этого задания, `.env` ETL. Старые практики не используются; допускается только `DB_SCHEMA=practice_2026_10_05`.

Справочники калькулятора и коэффициенты расчета загружаются из PostgreSQL. Неизвестный ID возвращает `-1`; недоступность БД/таблиц дает HTTP 503 и сообщение в интерфейсе. Значения размеров передаются десятичными строками и рассчитываются через Decimal. Копии `discount.py` и `material_calculator.py` из этой папки удалены: сервер импортирует единое ядро задания 2.
