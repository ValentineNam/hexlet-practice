# Разработка UI, навигации и CRUD-форм

## Подготовка Python-окружения

Команды ниже выполняются **из каталога этого этапа**, в bash/zsh на macOS/Linux.
Требуется Python 3.11 или новее с модулями `venv` и `pip`; проверено на Python 3.13.
Все четыре этапа используют одно окружение `../.venv` и общий `../requirements.txt`.
При первом запуске создайте окружение и установите зависимости:

```bash
python3 -m venv ../.venv
../.venv/bin/python -m pip install -r ../requirements.txt
../.venv/bin/python -m pip check
```

Если общее окружение уже создано, повторно создавать его не нужно. Команды используют
его интерпретатор явно: активация не требуется. Системный `python3` после установки
по-прежнему может не видеть пакеты — запускайте приведённые ниже команды через `../.venv/bin/python`.
Для Windows PowerShell процедура и замена пути описаны в [общем README](../README.md).


## Итоговое приложение

Эта папка объединяет итоговые части практик 14.09, 21.09 и 28.09:

- `MainWindow`: список партнеров из PostgreSQL, контактные данные и скидка по сумме реализации; в шапке есть иконка приложения и отдельный логотип компании.
- `PartnerEditWindow`: создание и редактирование партнера через `POST`/`PUT`.
- `PartnerHistoryWindow`: история реализации партнера через `JOIN` к `products`.
- Калькулятор материалов вызывает общий метод из `material_calculator.py`.
- SQL динамических запросов параметризован; CRUD-ошибки пишутся в `app.log` и возвращаются в UI.

Все экраны используют схему `practice_2026_10_05`, создаваемую заданием 1 этой практики.

## Запуск

1. Создайте общее окружение по инструкции выше и выполните ETL этапа 1 в вашей учебной БД.
2. Используйте `.env` этапа 1: backend читает его автоматически. Второй `.env` необязателен. Если он уже есть в этом каталоге, проверьте, что параметры совпадают: локальный файл имеет приоритет. Для отдельной конфигурации скопируйте `.env.example` в `.env` и заполните параметры.
3. Из **этой папки** запустите сервер:

```bash
../.venv/bin/python -B server.py
```

4. Откройте `http://127.0.0.1:8010/index.html`. Остановка — Ctrl+C. Если порт занят, остановите собственный предыдущий экземпляр или выберите свободный `PORT`; live-тесты этапа 4 ожидают именно 8010.

PostgreSQL нужен для данных UI, CRUD, истории и справочников. HTTP-сервер может запуститься без БД, но API покажет ошибки соединения. Это не подтверждает полноценную работоспособность приложения.

Сервер и калькулятор используют общее подключение из `../Реализация ядра бизнес-логики (Расчеты и алгоритмы)/database.py`. Приоритет: переменные процесса, локальный `.env` этого задания, `.env` ETL. Старые практики не используются; допускается только `DB_SCHEMA=practice_2026_10_05`.

Справочники калькулятора и коэффициенты расчета загружаются из PostgreSQL. Неизвестный ID возвращает `-1`; недоступность БД/таблиц дает HTTP 503 и сообщение в интерфейсе. Значения размеров передаются десятичными строками и рассчитываются через Decimal. Копии `discount.py` и `material_calculator.py` из этой папки удалены: сервер импортирует единое ядро задания 2.

## Проверки

```bash
../.venv/bin/python -B -m unittest discover -s tests -v
```

Тесты используют mock-соединения и временный локальный HTTP-сервер; PostgreSQL и `.env` не нужны. Для настоящего CRUD используйте отдельно подготовленную учебную БД, не рабочие данные.

## Проверки и доработки этапа 3

- Сервер отдаёт только файлы из явного списка `PUBLIC_ASSETS`. Запросы к исходникам,
  `.env`, логам, тестам, README и вложенным путям возвращают 404; каталог не индексируется.
- Форма редактирования не позволяет сохранить запись до завершения загрузки.
- Тип партнёра проверяется на клиенте и на сервере общим валидатором.
- После редактирования или возврата из истории восстанавливается выбор партнёра.
- Уникальные ограничения PostgreSQL возвращают HTTP 409; прочие нарушения
  целостности больше не объявляются ошибкой дублирования ИНН/email.

Проверка HTTP-раздачи без подключения к БД:

```bash
../.venv/bin/python -B -m unittest discover -s tests -v
```

**Ограничение проверки:** браузерные сценарии и работа CRUD с PostgreSQL должны
быть дополнительно проверены на машине, где доступен тестовый кластер.
