# Автоматизированное тестирование, аудит безопасности и UX

## Проверки итогового проекта

`test_final_app.py` проверяет:

- границы скидки и расчет/ошибку расхода материала;
- ETL по исходным CSV, включая отклонение строки с битым FK;
- валидацию партнерской формы;
- параметризацию `INSERT` с SQL-injection payload;
- настройку `app.log`.

Тестовые CRUD-вызовы подменяют соединение и не пишут в PostgreSQL.

## Запуск

Из этой папки и интерпретатором с зависимостями приложения:

```bash
python3 -m unittest discover -s . -p 'test_*.py' -v
```

## Результаты аудита

- CRUD SQL использует placeholders `%s` и передает пользовательские значения отдельно через `cursor.execute(query, values)`.
- Названия таблиц и полей заданы статически; сортировка и search path не строятся из пользовательского ввода.
- Валидация формы и backend проверяют обязательные поля, ИНН, email и рейтинг.
- Ошибки CRUD логируются с timestamp в `app.log`; UI показывает понятные сообщения.
- Перед уходом с измененной карточки приложение спрашивает подтверждение.

Дополнительно вручную проверьте интерфейс: ошибочный ввод, дублирующиеся ИНН/email, остановленный PostgreSQL, отмену с несохраненными изменениями и успешный CRUD в схеме `practice_2026_10_05`.

## Единое ядро после этапа 2

`test_core_discount.py` и `test_core_material.py` запускают тесты из задания бизнес-логики. Локальные копии алгоритмов удалены; обычные тесты подменяют чтение коэффициентов явно и не требуют рабочей БД. Реальные PostgreSQL/HTTP-сценарии запускаются отдельно из задания 2 по его README. В этом каталоге проходят 19 тестов; часть из них повторяет канонический набор ядра и не является отдельным покрытием.
