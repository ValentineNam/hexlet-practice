# Инфраструктура данных и ETL (База данных в 3NF)

## Состав

- `raw/partners_raw.csv`, `raw/products_raw.csv`, `raw/sales_history_raw.csv` — неизмененные файлы заказчика, скопированные из `DEV`.
- `schema.sql` — PostgreSQL-схема в отдельном namespace `practice_2026_10_05`.
- `etl.py` — единый import pipeline: чтение исходников, очистка, валидация, загрузка и контрольные counts.
- `select_count.sql` — независимый SQL-аудит уже импортированных таблиц.
- `etl_rejections.csv` — отчет по строкам, которые ETL отклонил; генерируется запуском.

## Нормализованная модель

- `partners`: ключ партнера, название без юридической формы, отдельный тип, ИНН, email и рейтинг (если в сырье рейтинг отсутствует, применяется 0 по умолчанию).
- `products`: ключ продукта, уникальное название, прайс-листовая цена.
- `sales_history`: одна строка на запись реализации, ссылки на партнера и продукт, дата, количество и цена за единицу на момент продажи.

Юридическая форма вынесена из наименования в отдельный атрибут. Названия продуктов и цены не дублируются в строках продаж. Итоговая сумма строки не хранится, а вычисляется как `quantity * unit_price_at_sale`, чтобы не создавать производное поле. `unit_price_at_sale` сохраняет историческую цену реализации отдельно от текущей цены товара.

## Что чистит и проверяет ETL

- Обрезает и сжимает пробелы в текстовых полях, очищает `...` перед именем партнера, нормализует `A.B.` в `А.В.`.
- Читает `partners_raw.csv` как UTF-8, `products_raw.csv` как CP1251, `sales_history_raw.csv` как UTF-8.
- Поддерживает форматы дат `DD.MM.YYYY`, `YYYY/MM/DD`, `YYYY-MM-DD`, `DD-MM-YYYY`, `YYYY.MM.DD` и загружает их как PostgreSQL `DATE`.
- Проверяет обязательные значения, уникальность ключей/ИНН/email, положительное количество, числовые цены и соответствие `amount = quantity * product price`.
- Не загружает продажу с отсутствующим партнером/товаром; записывает файл, строку и причину в `etl_rejections.csv`.
- Все валидные партнеры, продукты и продажи загружаются одним транзакционным запуском; после загрузки та же команда печатает counts и число битых FK.

Для предоставленных исходников ожидается: 5 партнеров, 3 продукта, 5 продаж загружено; 1 продажа с `partner_id=999` отклонена и записана в отчет. Исходные CSV не изменяются.

## Подготовка и запуск

1. Установите зависимости: `python3 -m pip install -r requirements.txt`.
2. При необходимости создайте `.env` рядом с `etl.py` по примеру `.env.example`; локальный файл имеет приоритет. Если его нет, ETL использует `.env` backend-задания практики 14.09.
3. Выполните из этой папки:

```bash
python3 etl.py
```

Скрипт создает/использует только схему `practice_2026_10_05`, затем очищает и загружает таблицы этой схемы. Схемы и таблицы предыдущих практик не удаляются и не меняются. Повторный запуск воспроизводит импорт заново внутри этой целевой схемы.

Для отдельной проверки после импорта:

```bash
psql "$DATABASE_URL" -f select_count.sql
```

Тесты преобразования без подключения к БД:

```bash
python3 -m unittest discover -s tests -v
```
